# 🧪 Standalone Data Science & Machine Learning Stack Guide

Welcome! If you are stepping into the world of Data Science (DS) and Machine Learning (ML) for the first time, or if you are looking to set up an advanced, production-ready machine learning workstation with GPU acceleration—this guide is built for you.

We start from absolute beginner analogies and work our way up to expert configurations across Windows, macOS, and Linux.

---

## 🧪 What is the Data Science Stack? (For Complete Beginners)

Imagine you are setting up a state-of-the-art **molecular gastronomy kitchen**. 
- You need a kitchen space, ingredient suppliers, isolated cooking zones, recipe cards, and highly specialized cooking tools.
- In data science, before environment management and standard stacks, we had the **"library soup"** problem. If Project A needs Python 3.8 and Scikit-Learn 0.24, and Project B needs Python 3.11 and Scikit-Learn 1.2, installing them globally on your computer will break both.

### The Scientific Kitchen Analogy:
- **Python (The Kitchen Space)**: The foundation where everything is built.
- **Pip & Conda (The Ingredient Suppliers)**: Package managers that fetch libraries from the internet and deliver them to your kitchen.
- **Virtual Environments (Isolated Cooking Stations)**: Independent cooking blocks. What you cook in Station A (libraries for Project A) does not cross-contaminate Station B.
- **Jupyter Notebooks (The Recipe Cards & Lab Log)**: An interactive document that allows you to write python code, execute it in individual blocks, and instantly see charts, tables, and model outputs right under the code.
- **Libraries (The Specialized Tools)**: Specialized appliances like blenders, scales, and ovens that perform mathematical analysis, chart plotting, and model training.

## 💻 Platform Setup & Expert GPU Acceleration

Training deep learning models requires massive parallel computation. Running on a Graphics Processing Unit (GPU) is **10x to 100x faster** than running on a Central Processing Unit (CPU).

Choose your operating system below for detailed setup instructions.

### 🪟 1. Windows Setup (WSL2 + NVIDIA CUDA)

For data science, running inside Windows Subsystem for Linux (WSL2) is highly recommended because many advanced ML libraries (like deep learning accelerators) run natively on Linux and have limited Windows support.

#### Option A: WSL2 Linux Environment (Recommended for Deep Learning)
1. **Ensure WSL2 & Docker Desktop** are installed (see [Docker Guide](docs/docker-guide.md)).
2. **Install NVIDIA Host Driver**: Install the latest official NVIDIA game-ready or studio driver on your Windows host. This driver includes WSL2 GPU support automatically.
3. **Install CUDA Toolkit inside WSL2 (Ubuntu)**:
   Inside your WSL2 terminal, download and install CUDA:
   ```bash
   # Add NVIDIA key and repository
   wget https://developer.download.nvidia.com/compute/cuda/repos/wsl-ubuntu/x86_64/cuda-wsl-ubuntu.pin
   sudo mv cuda-wsl-ubuntu.pin /etc/apt/preferences.d/cuda-repository-pin-600
   wget https://developer.download.nvidia.com/compute/cuda/12.4.0/local_installers/cuda-repo-wsl-ubuntu-12-4-local_12.4.0-1_amd64.deb
   sudo dpkg -i cuda-repo-wsl-ubuntu-12-4-local_12.4.0-1_amd64.deb
   sudo cp /var/cuda-repo-wsl-ubuntu-12-4-local/cuda-*-keyring.gpg /usr/share/keyrings/
   sudo apt-get update
   sudo apt-get -y install cuda-toolkit-12-4
   ```
4. **Configure PATH**: Add the following to your `~/.bashrc`:
   ```bash
   export PATH=/usr/local/cuda-12.4/bin${PATH:+:${PATH}}
   export LD_LIBRARY_PATH=/usr/local/cuda-12.4/lib64${LD_LIBRARY_PATH:+:${LD_LIBRARY_PATH}}
   ```
5. **Verify GPU in PyTorch**:
   Create a virtual environment, install PyTorch with CUDA support, and run:
   ```bash
   python3 -c "import torch; print('CUDA Available:', torch.cuda.is_available()); print('Device Name:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'None')"
   ```

#### Option B: Native Windows (Anaconda Setup)
1. Download and install [Anaconda Individual Edition](https://www.anaconda.com/download) or the lightweight [Miniconda](https://docs.conda.io/en/latest/miniconda.html).
2. During setup, check **"Add Anaconda/Miniconda to my PATH environment variable"** (or use the *Anaconda Prompt* from your Start Menu).

### 🍎 2. macOS Setup (Apple Silicon GPU Acceleration)

Apple Silicon Macs (M1, M2, M3, M4) do not support NVIDIA CUDA. Instead, Apple uses its own unified graphics system accessed via **Metal Performance Shaders (MPS)**.

#### Step-by-Step Installation:
1. **Install Homebrew**: Open Terminal and run:
   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```
2. **Install Miniforge**: Miniforge is a conda distribution compiled natively for Apple Silicon (arm64), avoiding translation overhead:
   ```bash
   brew install miniforge
   conda init $(basename $SHELL)
   ```
   *Close and restart your terminal.*
3. **Configure PyTorch Apple Silicon GPU (MPS)**:
   Create an environment and install PyTorch:
   ```bash
   conda create -n ml-env python=3.10 -y
   conda activate ml-env
   pip install numpy pandas scikit-learn matplotlib jupyterlab
   pip install torch torchvision
   ```
4. **Test MPS in Python**:
   Verify PyTorch can use the Apple Silicon GPU:
   ```python
   # test_mps.py
   import torch
   print("MPS (Apple Silicon GPU) Available:", torch.backends.mps.is_available())
   # Initialize tensor on GPU
   x = torch.ones(5, device="mps")
   print(x)
   ```

```bash
sudo reboot
```

#### 🛠️ Linux Expert-Level JupyterLab Service Setup:
Instead of starting JupyterLab manually in your terminal, set it up as a system background service (daemon) that launches automatically on system boot.

Create the file `/etc/systemd/system/jupyterlab.service`:
```ini
[Unit]
Description=JupyterLab Server
After=network.target

[Service]
Type=simple
User=YOUR_SYSTEM_USERNAME
WorkingDirectory=/home/YOUR_SYSTEM_USERNAME/projects
ExecStart=/home/YOUR_SYSTEM_USERNAME/miniconda3/envs/ml-env/bin/jupyter-lab --no-browser --port=8888 --ip=0.0.0.0 --NotebookApp.token='your_secure_token'
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```
*Enable and start the service:*
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now jupyterlab
```
You can now access your notebooks anytime by browsing to `http://YOUR_SERVER_IP:8888` using the security token you configured.

## 📦 Environment & Dependency Managers (Deep Dive)

### 1. `venv` + `pip` (Lightweight Standard)
- Best for: Web apps, microservices, lightweight projects.
- Usage:
  ```bash
  python3 -m venv .venv
  source .venv/bin/activate
  pip install -r requirements.txt
  ```

### 2. `conda` & `mamba` (Binary Environments)
Conda handles C-compiled libraries (like CUDA binaries) much better than pip. However, Conda is notoriously slow at resolving dependencies.
- **Mamba** is a C++ drop-in replacement for Conda that resolves environments in seconds:
  ```bash
  # Install Mamba via Miniforge/Homebrew
  conda install -c conda-forge mamba -y
  
  # Create environment using mamba (10x faster)
  mamba create -n ds-env python=3.10 numpy pandas scikit-learn -y
  mamba activate ds-env
  ```

### 3. `poetry` (Production Gold Standard)
Poetry guarantees reproducible environments by creating a lockfile (`poetry.lock`). It manages virtualenvs automatically and prevents version drift in production code.

**Example `pyproject.toml` configuration for a Data Science project:**
```toml
[tool.poetry]
name = "data-science-project"
version = "1.0.0"
description = "Production ML Pipeline"
authors = ["Your Name <email@example.com>"]

[tool.poetry.dependencies]
python = "^3.10"
numpy = "^1.24.0"
pandas = "^2.0.0"
polars = "^0.18.0"
scikit-learn = "^1.2.0"
torch = {version = "^2.0.0", source = "pytorch-src"}
jupyterlab = "^4.0.0"

[[tool.poetry.source]]
name = "pytorch-src"
url = "https://download.pytorch.org/whl/cu118"
priority = "explicit"

[build-system]
requires = ["poetry-core>=1.0.0"]
build-backend = "poetry.core.masonry.api"
```

## 🐚 Windows CMD vs. PowerShell vs. Linux/macOS Bash

### 1. Activating Virtual Environments
- **Bash (Linux/macOS/WSL)**:
  ```bash
  source .venv/bin/activate
  ```
- **PowerShell**:
  ```powershell
  .venv\Scripts\Activate.ps1
  ```
  *Note: If you get a permission error in PowerShell, run `Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope Process` first.*
- **Windows Command Prompt (CMD)**:
  ```cmd
  .venv\Scripts\activate.bat
  ```

### 2. Running JupyterLab in the Background
- **Bash (Linux/macOS/WSL)**: Runs Jupyter in the background and saves logs to a file:
  ```bash
  nohup jupyter lab --no-browser --ip=0.0.0.0 > jupyter.log 2>&1 &
  ```
- **PowerShell**: Starts a background process:
  ```powershell
  Start-Process jupyter-lab -ArgumentList "--no-browser", "--ip=0.0.0.0" -NoNewWindow
  ```
- **Windows Command Prompt (CMD)**:
  ```cmd
  start /b jupyter lab --no-browser --ip=0.0.0.0 > jupyter.log 2>&1
  ```

### 3. Resolving Path Conflicts
If CMD or PowerShell complains that `python` or `pip` is not recognized, you must add the path manually for your current terminal session:
- **Windows Command Prompt (CMD)**:
  ```cmd
  set PATH=C:\Users\YourUsername\AppData\Local\Programs\Python\Python311\Scripts;C:\Users\YourUsername\AppData\Local\Programs\Python\Python311;%PATH%
  ```
- **PowerShell**:
  ```powershell
  $env:PATH = "C:\Users\YourUsername\AppData\Local\Programs\Python\Python311\Scripts;C:\Users\YourUsername\AppData\Local\Programs\Python\Python311;" + $env:PATH
  ```
